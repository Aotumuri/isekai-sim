# 首都防衛の戦線割当と実行の観測

## 事前に定めた判定条件

開戦時の防衛国の首都を一つ選び、既存の首都脅威評価が選んだ主戦線を追う。計画・配分・掩護位置・実移動はそれぞれの状態から読む。採択時のキャンペーン理由、前線計画の理由フラグ、配分の欠員、前線上の戦力、首都の在留戦力を分ける。配分先の変更を部隊の離脱や移動開始と同一視しない。戦線の存続・消滅と、部隊の転属・既知の拘束・所在不明を区別する。収納先を確認できた部隊は輸送中と記録する。標本で原因が分からない場合は不明とする。

既知の膠着790・792の最初の600 tickを観測し、首都が空になった場合の直前の割当・目的地・実移動を比較する。同一シードで観測有無の全 tick の主要状態、戦争履歴、乱数状態が一致することを必須とする。再生2回で観測が一致し、履歴上限に達しても計数は継続することを確認する。観測は診断から明示的に起動し、通常プレイに処理・履歴を加えない。この比較は機序の探索に用いる。

## 初回の比較

`node --import tsx test/diagnostics/war-ai-capital-front-execution.ts 822748319790 /tmp/front-790.json`。792は末尾3桁を変えて実行する。エンジン `42d9070` で各601標本を観測した。両ケースで診断の有無による各 tick の状態・戦争履歴・乱数の差はなく、観測2回のイベントも一致した。記録331・232件、欠落0件。観測処理の計測は各約11 ms。通常プレイはこの診断を呼び出さない。

| 膠着 | 所在と実行 | 割当との関係 |
|---|---|---|
| 790 | 首都は290 tickに無人となり302 tickに陥落。最後の `unit-48` は290 tickにフィールド・輸送積荷の双方から観測できなくなった。 | 唯一の在留部隊の最終目標は首都。出発による空白は確認されていない。 |
| 792 | 226 tickで `unit-61` と `unit-71` が首都からそれぞれ `meso-80` と `meso-99` に到着。首都は376 tickに陥落。 | 両部隊は同じ戦線に残り、別の守備位置へ移動した。主戦線の解体・転属による出発ではなかった。最初の脅威評価から合計198 tickは首都が無人だった。 |

両例とも脅威下で主戦線・計画・配分があり、支配中の前線地区に実在する割当済み部隊の戦力は計画上の必要量を下回った。首都在留の計数は地区IDに基づく。戦力は既存の `getUnitCombatStrength` を用い、燃料在庫は別に記録する。観測は slow tick の更新と次の fast tick の実行を区別する。旧移動目標と新規の守備位置が一標本だけ食い違う例は、持続する実行不一致には数えない。フィールドにも積荷にも見えない部隊の死因や、初めて追跡された部隊の生産理由はこの観測では特定できない。

792の210 tickには同じ戦線の `unit-61` が割り当てられていた `meso-72` が `unit-58` に渡り、`unit-61` は `meso-80` に付け替えられた。230 tickにも `unit-71` から `unit-61` へ `meso-99` の引継ぎがあった。守備位置が存続している場合に、部隊ID順の貪欲割当で前任の位置を消費する可能性を次に隔離検証する。
