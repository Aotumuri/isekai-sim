## 目標と終戦を観測した試作1の評価

`042e785` の同一ソースで、機能の無効・有効を各200件実行した。
通常ループを変更せず、診断ドライバだけに任意のtick観測を追加した。
観測は開戦時に固定した限定目標または自領保全、達成時刻、終戦時刻、
損耗、存続を記録する。内部目標そのものの合理性を保証する指標ではない。
同じ外交経過を強制しないため、新規開戦の集合がA/Bで変化する。
平均率にはその選択の影響も含む。終了していない戦争を、期間平均から
黙って除外した結論にせず、unfinishedWarSidesと併記する。

無効群200件の終了時ゲーム指標は、CPU計測値を除いて旧ソースの基準と
全件一致した。観測追加と既定無効の試作は、この範囲で既存動作を維持する。

試作1は採用しない。active-war では限定目標保持率がシード平均で
1.8ポイント低下、国家存続率は6.7ポイント上昇、未終結の戦争側数は
平均1.8増加した。long-frontline では目標保持率が10ポイント低下し、
終結した戦争の期間平均も135 tick増加した。首都陥落の減少だけを
品質改善と判断することはできない。

コードと状態から確認した問題は次の通り。

- 防衛方針が全国の局所攻撃機会を一律に禁止していた。
- 強制・旧式戦争には交渉による終結がないのに、限定目標達成後に
  攻勢を止める方針が適用されていた。
- 攻撃から維持へ方針を変更しても、必要兵力が攻撃時の値のままだった。
- 既存作戦の準備・実行の継続と、国家方針の更新が調整されていなかった。
- 国家の戦力集計に輸送中の陸上部隊が含まれていなかった。

試作2では上記を修正し、和平後に内部目標が実際に確保されるかを
評価する接続を追加した。占領中というだけでは和平による目標確保と
みなさず、領土の法的保有または和平条項による譲渡を評価する。
既存の和平成熟期間・条件検証・プレイヤー承認は維持する。

`--observe-wars` で追跡を有効にし、`--normal-wars --full-systems` で
既存の強制戦争フラグを外して、通常の交渉可能な戦争として両群を測定できる。
強制戦争群と通常戦争群の成績を直接A/Bとして比較しない。
試作2の実証と未使用シード評価は未完了で、既定無効を継続する。

AI全体の改善とみなすことはできない。これらは開発シードでの結果である。

悪化例を調べると long-frontline の seed 822748319788 で移動が23→405、
collapse-advance の同seedで1→432となっていた。継続中の食料危機が
毎回の国家再評価を許可し、首都危機との間で方針が切り替わる経路があった。
試作4は危機への新規突入とその継続を区別して維持期間を適用する。
また、主敵を選ぶ際に首都を脅かす敵を明示的に優先する。

従来の中立な開始時目標は変えず、観測schema 2で領土価値の利得・損失と
作戦終了理由を追加した。地域価値の式は既存の領土評価と共有するが、
観測側は人口や領有記憶を初期化しない。価値は開戦時に固定し、後の価格・
人口変化による見かけの利得を含めない。新指標は無効群・有効群を同じschemaで

通常群では後発の戦争集合が変わるため、開始時戦争と自発的な後発戦争の
指標を分ける。新しい目標選択を実装したことを理由に、中立な目標定義や
シード、開始条件を変更しない。未使用シードは依然として未着手である。

## 長時間・メモリの検証

試作4の通常自律世界は両群3シード、各100000 fast tick（仮想時間約2.78時間）を
完走した。`war-ai-long-v4-comparison.json` に比較を保存する。
通常のベンチマークのheap値はGC実行時刻に左右され、maxRSSはプロセス全体の
高水位であるため、この値だけでメモリリークを判断しない。

GC後の保持heapと計画状態を追跡する診断も追加した。

```sh
node --expose-gc --import tsx test/diagnostics/war-ai-soak.ts --ticks 100000 --seeds 3 --output diagnostics/war-ai-soak-v4.json
```

同じシードを両群で実行し、順番を交互にする。10000 tickごとにGCを行い、
保持heap・RSS・CPU・所要時間・戦争数・部隊数を保存する。GCは計測区間外に置く。
戦略tickごとに計画数、目的数、履歴100件、変更記録200件の上限を検査する。
区間末には目的地域の実在、国家存続、部隊位置と有限な兵力値も検査する。
この診断は観測の負荷を含み、異なる戦争経過のCPU差を純粋なコード差とは
解釈しない。GC後の推移と状態の上限を併せて評価する。

## 既定条件・表示の確認と未使用評価の方針

政治変動込みの統合条件でもA/B各260件が完走した。
全260対について、実行設定（campaignフラグ以外）と開始時の領域数・国家数・
兵力数・戦争数・補充在庫が一致することを検査した。
結果は `war-ai-app-v4-comparison.json`。開発群では領土価値の利得・損失は
複数の条件で良化した一方、膠着・資源制約などでは悪化も残る。
中立目標の攻撃側・防御側の成績は逆方向に変わる場合があり、一方だけを抜き出さない。

未使用群では、同じ実装・同じ13シナリオ・同じ10000 tick・各20シードで
政治変動も有効にする。主に領土価値の利得と損失、損耗、戦線間移動、
未終結を併せて見る。中立な目標保持率、分布、最悪例、CPUも省略しない。
戦争集合の変化を区別するため、移動の生件数と戦争側の活動時間あたりの
件数を併記する。都合の良い指標だけの合成点は作らない。

既定320000領域の性能確認は両群2シードを完走した。シミュレーション時間は
seed 822748319780 で25884→18910ms、seed 822748319781で15704→18267ms。
後者のCPU時間は17282→21453msで増加した。既存の経路探索時間の差が大きく、
JIT・戦争経過・キャッシュに左右されるため、一律の高速化とは主張しない。
生成を含む時間、heap、maxRSS等の全値は `war-ai-default-scale-v4.json` に保存した。

政治変動込みのGC追跡も全6件が完了し、終盤の保持heapは約38〜42 MiB。
計画・履歴の上限違反、無効な地域ID、非有限な兵力値は検出されなかった。
大きなマップのGC前heapと、この小規模長時間検証のGC後heapを混同しない。

表示は `war-ai-preview.html` をVite経由で開き、実際のデバッグ描画を確認した。
国家方針、優先相手、目標、達成・未達、作戦結果が表示され、30秒進める操作で
更新されることを確認した。上部ボタンとの重なりを修正した。
