# 国家シミュレーションの自然開戦パイロット

## 事前に定めた比較

戦費の会計修正後 `42d9070` と今回の統合版を比較する。全社会システム・キャンペーンを有効にして、外部の固定開戦を入れない640×360 quickマップを10,000 fast tick進める。開発シードの780・788・799を使う。終戦した請求、選挙制約が発生した見送り、指揮官の発進判断、自然開戦への曝露を数える。発生が少ない場合は到達件数だけを報告する。戦争の勝敗による採否を評価しない。

プロセスCPUは生成を除いた同実行区間の値、ヒープは100 fast tick間隔の標本最大値と終了GC後を報告する。CPU中央値が20%を超えて増えれば、同一状態での追加費用を分けて調べる。性能差は異なる軌跡やV8の状態も含む。最終保留シードは使わない。

## 結果

比較版は `40ddcbe`。表の値は会計修正直後 → 比較版。各実行を別のNode 24プロセスで開始し、同時実行を避けた。

| 開発シード末尾 | 自然開戦 | 最大部隊数 | CPU (ms) | 最大標本ヒープ (MiB) | 終了GC後 (MiB) |
|---|---:|---:|---:|---:|---:|
| 780 | 2 → 2 | 112 → 112 | 2,798 → 2,833 | 78.6 → 79.3 | 33.4 → 33.4 |
| 788 | 7 → 8 | 427 → 412 | 6,986 → 6,432 | 124.7 → 110.2 | 36.8 → 37.6 |
| 799 | 6 → 5 | 216 → 220 | 4,630 → 4,443 | 96.0 → 87.6 | 35.5 → 35.6 |

開始時GC後は21.4–21.5 MiB。CPU中央値は4,630 → 4,443 msで約4.0%減。軌跡差を含む。788で追跡した請求1件は未達で終結。指揮官判断は788で3件、799で1件あり、すべて発進した。得点による領土請求の見送りは発生しなかった。選挙による見送りと慎重な指揮官の待機に関する自然発生時の性能・有効性は未判定。

再現は `node --expose-gc --import tsx test/diagnostics/architecture-pilot-replay.ts <engine-root> <全桁のseed>`。対象版の `src/` と `test/` を `git archive` で展開し、同じ依存関係を参照させる。開戦件数はslow tickで観測された個別開戦の数で、同じ標本間に始まり終わった戦争は含まれない。

次の比較では、開戦前に有効な請求があり選挙を控えた政府、または通常の発進準備率60–70%に達する作戦が実際に観測された開発ケースを対象にする。選挙支持と発進待機それぞれについて、転帰・実行時間・見送りの費用を対照する。現段階の機序の確認を踏まえ、忠誠や命令遅延などの追加制度はそれぞれの判断に必要な証拠が得られた段階で扱う。
