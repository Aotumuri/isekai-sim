# 外国政治支援の審査時期の比較

## 時間の不一致

比較元はローカル `main` の `456992c`。変更前の回帰テストは884件すべて合格した。1 slow tick は世界の10日に当たる。地域要求は `updateTerritorialGovernance` の100日周期で、不満・排除・地域内人口の条件を満たしたときに開く。政府の初回審査は通常100日後、提示された条件への運動の返答はさらに100日後。戦時の延期、占領、領土移転、支持基盤の喪失や全国政策による早期解決で、この期間は変わる。

`stepSlowTick` は宗属政権、亡命政権、請求権を更新した後、外国政治影響を実行する。国内政治、外交、ファクション、領土処理、地域統治がその後に続く。同じ tick の審査からは地域統治が新たに開いた要求がまだ見えない。外交関係の定例更新は100日おき。支援審査では、その定例更新を待たず、評価時点で有効な国境・条約・ファクションの接触を使う。国境索引は領土のバージョンで更新される。条約は期限を過ぎれば、その後の外交更新が物理的に削除する前でも接触要件を満たさない。支援が政府の審査前に成立すれば、その後の意思決定が支援を参照する。

変更前の221国・3,650日、シード `822748319780` の旧診断を再実行した。閉じた13件の寿命はすべて100日で、12件が600日周期の外国評価と重ならなかった。旧診断は日末の状態から評価を推定し、同日中の呼び出し順や同じ地区の再開を区別しない。呼び出しを直接観測したAでは、同じ3,650日間で審査なしの終結は9件だった。旧集計のように、政府判断と同じ日に審査が先に走った要求を見逃したと数えると、差を過大評価する。

## 比較した方式

| 方式 | 新規支援の候補を探す時期 | 審査範囲 |
| --- | --- | --- |
| A | 600日おき | 現行の全域接触索引と生存中の地域要求 |
| B | 要求が開いた次の slow tick | 同じ tick に開いた要求をまとめ、該当地域の政府に接触する国のみ抽出 |
| C | 100日おき | 生存中の要求を持つ政府への接触のみ抽出 |

いずれも新規支援の開始条件は2,400日目。Bもこの最初の境界ではその時点の要求を参照する。以降は既に評価した同じ要求を再列挙しない。イデオロギー活動は600日おき、既存支援の更新と減衰は100日おき。600日周期の処理と重なる場合はイデオロギー活動用の接触索引を共有する。

Bの保留情報は世界・地区ごとに一件で、政府ID、作成 tick、要求世代の識別子を持つ。識別子を要求オブジェクトの弱参照索引に付け、キュー自体には要求オブジェクトを保持しない。同じ地区で再開すれば旧世代の枠を置き換える。次の tick で一度取り出し、現行の要求との世代・政府・地区所有者・状態を確認する。閉じた要求、削除済みの要求、置き換えられた世代は候補に入らない。国家が同じまま内閣が交代した場合、審査時点の現職政府を評価する。同一バッチの審査順序は地区IDと従来のスポンサー比較で決まる。全国家を要求ごとに調べる処理はなく、接触の元データをバッチごとに一巡する。保持件数は同時に作成された地区数に従い、任意の上限で要求を切り捨てない。

提案ルールは共通。接触、戦争・危機、宗属関係、関心度、外交影響力、クールダウン、上限、運動の受否、外交摩擦を既存の `political-advocacy.ts` で処理する。同じバッチの提案直前にも現行の要求、所有、スポンサーの状態、上限、クールダウン、影響力を再確認する。この間に新しい接触を作る外交更新は走らない。提案は拒否でも22を消費し、承諾時のみ枠を使用する。維持費と更新条件も共通。

## 制御ケースと因果

- 200日で合意する要求。作成前にその日の外国審査が終了する順序で、Aは見逃し、Bは10日後に1回、Cは100日後と200日後に審査した。Cの初回は同じ日の政府判断より先だった。
- 同一スポンサーと複数の同時要求。承諾は初回の1件で22を消費し、後続はクールダウンを再確認した。既存の回帰ケースで同時上限2件、拒否による消費1回と枠の温存、更新・失効も確認した。登録順を逆転し、診断有無を変えても結果は一致した。
- 同じ地区で要求が置き換わった場合、解決済みの場合、要求が削除された場合に、古いイベントから支援は成立しなかった。次に開く世代は独立に一度だけ審査した。形成直後のファクション接触は候補に入り、評価時点で期限切れの条約接触は候補から外れた。適格スポンサーがいない場合は審査を記録し、影響力は消費しなかった。
- 同じ国内状態で実際の政府判断と支援項だけを除いた判断を比較した。閾値近傍の制御ケースでは「拒否→保護の提案」「部分提案→全面提案」「全面提案→部分提案」を確認した。保護要求では、自治を提案する閾値をまたいでも条件が同じなら「全面提案→全面提案」と数える。比較は乱数を使わず、世界に適用するのは実際の判断一度だけ。
- 政府が出した提案に対する運動の返答は別段階。既存の実装では、支援による厳しい受諾条件が従来条件との論理和に置かれ、有効な支援強度の範囲で返答を変えない。今回は挙動を維持し、その返答を政府判断の因果計数から外した。

## 決定性と検証

小782のAは比較元と世界状態のSHA-256が一致した（`46ab83cd36fd…`）。同シードでBを指定した実行と、同じ設定で方式指定・支援観測フックを外した既定動作の再実行も一致した（`81d8e44bf965…`）。A/B/Cの間で提案が異なった小782、中788、221国通常では、外交影響力や関係の変化により署名の差が生じうる。経済、軍事や領土ルールに審査方式による分岐は追加していない。

`npm run test:typecheck`、`npm test`（893件）、`npm run build` は合格。ビルドではViteのチャンクサイズ警告が出た。シェルの既定Nodeは共有ライブラリの欠落で起動しなかったため、既にインストールされていたNode 24.22.1を使用した。

## 採用と残る課題

Bを標準に採用した。100日方式と比べて、政府が審査できる最初の日を待たず、要求が開いた直後の外交状態で一度だけ判断できる。100日方式はキューが不要だが、短命の要求を境界まで待たせ、長寿命の要求を再評価する。600日方式は比較対照として残した。全シナリオの初回判断前の審査はBとCがともに99件中82件。遅延中央値はBが10日、Cが100日だった。221国通常の審査CPUはAが4.57 ms、Bが19.07 ms、Cが9.59 ms。Bはこの世界で期末に残った1件を先に審査し、候補確認もCより16件多かった。Bの審査CPUはこの条件で総CPUの約0.02%であり、早期に審査する利点を優先した。

自律実行において、外国支援を経た後の歴史の違いは、個別の政府判断が変わったことを意味しない。新規支援が成立しなくても、提示して拒否された時点で影響力と二国間関係が変わる。後続の戦争・政策・地域要求はその時点から分岐しうる。221国通常のBでは154候補中80が影響力不足、67が関心不足、4が戦争・危機で外れ、適格な3件の提案は運動がすべて拒否した。小782ではクールダウンが主な排除理由だった。現時点ではこれらを閾値の欠陥と判断する根拠がない。全戦争・革命や合意の累積値は再現コマンドの `historyCounts` と `counters` で確認できる。

初期2,400日の抑制はどの方式にも残る。外交条件が後で変わってもBは同じ要求を再審査しない。664国は抑制期間内の性能比較で、支援候補が多い状態の負荷を測っていない。期間内に更新・失効を観測せず、長寿命の要求に対する動作は制御ケースが主要な証拠になる。次の開発段階では、閾値を調整する前に、候補の排除理由を寿命・政府判断の前後・外交環境で比較し、初回以降に本当に新しく有望になった接触がどれだけあるかを測る。

後続の[外国支援の再審査実験](FOREIGN_ADVOCACY_REASSESSMENT_EXPERIMENT.md)で、要求存続中の候補の変化と、政府判断への効果を測定した。

```sh
  for seed in 822748319780 822748319781 822748319782; do
    WORLD_SIGNATURE=1 WORLD_ADVOCACY_SCHEDULE=$schedule node --expose-gc --import tsx \
      test/diagnostics/long-term-world.ts quick "$seed" 20000
  done
  WORLD_SIGNATURE=1 WORLD_ADVOCACY_SCHEDULE=$schedule node --expose-gc --import tsx \
    test/diagnostics/long-term-world.ts medium 822748319788 3650
  WORLD_SIGNATURE=1 WORLD_ADVOCACY_SCHEDULE=$schedule node --expose-gc --import tsx \
    test/diagnostics/long-term-world.ts scale 822748319780 3650
  WORLD_SUBJECT_PAIRS=40 WORLD_SUBJECT_ACQUISITIONS=40 WORLD_SUBJECT_AUTONOMY=10 \
    WORLD_SIGNATURE=1 WORLD_ADVOCACY_SCHEDULE=$schedule node --expose-gc --import tsx \
    test/diagnostics/long-term-world.ts scale 822748319780 3650
  WORLD_SIGNATURE=1 WORLD_ADVOCACY_SCHEDULE=$schedule node --expose-gc --import tsx \
    test/diagnostics/long-term-world.ts dense 822748319780 100
done

```
