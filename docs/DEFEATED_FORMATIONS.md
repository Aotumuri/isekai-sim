# 敗走と捕虜

戦略上の撤退は、後衛と退避先を決める既存の撤退計画が担う。組織率ゼロによる戦闘離脱は別の処理で、現行エンジンでは残った人員を含めて編制を戦場から削除していた。海戦でも除去が起こるが、今回扱うのは陸戦で組織を失った編制に限る。

研究 PR #2 の R2.20 観測では、790 は旧候補で最初の首都を tick 242、燃料制約候補では tick 302 に失い、後者では安全な予備首都も失って tick 394 に滅亡した。792 では燃料制約候補で首都の有効守備隊が tick 226 以降にゼロとなり、tick 376 に滅亡した。一方、旧候補では撤退中の unit-66 が tick 328 に首都へ到着した。780 で確認した燃料切れ守備隊の説明をそのまま 790・792 に当てはめることはできない。出典は研究ブランチの `docs/AI_R2_MARCH_CONTROLLER_CONTROL.md` と `diagnostics/war-ai-r2-20-loss-window-{r1,fuel}-{790,792}.json.gz`。

## 試作のルール

- 組織を失った編制は戦場一覧から外れる。戦闘、移動妨害、占領、手動命令から外れる間も、募兵の上限には含まれる。
- 敵が占領・進入していない自国の隣接地区を地区 ID 順で選ぶ。撤退には最低でも歩兵の移動時間を要し、到着後は既存の再編における組織回復速度と復帰基準を使う。部隊 ID、経験、人員、携行装備を引き継ぐ。燃料切れの戦車部隊は装備を放棄して徒歩で撤退する。
- 退路がなければ戦闘相手または現地の敵が捕虜を取り、捕らえる側がいなければ未帰還として記録する。退避先が危険になった場合も同様に処理する。戦闘中の直接損害は別途計上する。
- 捕虜は拘束国、交戦国、出身国ごとに集計する。交戦終了から10 slow ticks 後に利用可能な政府へ人員だけが戻る。受け入れ政府がない場合は離散として記録する。武器や部隊の自動再生は発生しない。経過は既存の World history の Military フィルターで見られる。
- 手動交換、海戦の救助、隣接地区を越える敗走経路は今回の試作の対象外。両通常プリセットで有効。比較用の無効化は `defeatedFormationsEnabled: false`。
